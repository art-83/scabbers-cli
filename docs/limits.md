# External prerequisites and current limits

This application is implemented and locally verified. That does not mean live support or a NOLA production-ready rollout has been exercised.

- Support handles objective Bug, Bug Crítico, Ticket, duplicate and cancellation routes. Duplicates require an open verified Bug; cancellation requires a real reason field, an exact allowed option and an available cancellation transition. Product/information handoffs keep the Report open and never create an RFC. Missing mappings or a verifiable Jira link block the dependent action; ambiguous behavior requires a private decision.
- Jira metadata, required fields, squad compatibility, issue relationships, credentials and exact transition names must match the actual project. Current development checkpoints expect available In Progress, Docs & Tests and Ready for Code Review transitions. An intermediate mandatory workflow step needs a verified mapping before the dependent mutation can run. The controller does not modify Jira administration.
- The installed catalog skills and repository test dependencies must be configured. Test commands are trusted local configuration, not text selected by a report or an engine. Budget enforcement is currently per Claude turn (USD 5) and a ten-minute process deadline; there is no cross-engine daily financial budget accounting yet.
- Engines were checked against the installed Claude Code 2.1.310 and Codex CLI 0.165.0. Their native sessions are real. External native authentication expiry and protocol/version changes can block a run.
- The JEV cutoff is the preserved provisional form-v0.6 threshold, not a calibrated success probability. Missing/invalid JEV responses never grant approval. Provider-resource changes are excluded from automatic implementation here; no template activation or production-provider write is implemented.
- Slack Socket Mode configuration exists, but its app-level secret was not available in the checked local environment/references. Live buttons/DM events additionally need the corresponding app configuration. The supported baseline is persisted polling and decision-code replies; no app token is extracted from browser/plugin internals.
- Historical support backfill begins at the persisted initial setup watermark. The current configured schedule is used for historical received timestamps; schedule-version migration and legacy-ledger import are intentionally not implemented.
- Native Claude browser capability is conditional on the official Chrome extension/native host, connected browser, approved domains and login. Browser control was not exercised against remote applications in this delivery. Codex desktop-browser access is not a supported standalone CLI transport here. E2E returns blocked rather than falling back to Playwright or claiming an observation.
- Staging exists for NOLA web development. Live GitLab/Jira configuration, exact deployed revisions, pipeline/deployment visibility, endpoint access and browser sessions still need real environment validation. No NOLA staging integration/deploy or customer task E2E was performed in this delivery.
- A browser failure/rejected human E2E preserves evidence and conversation for investigation. A significantly revised attempt that would need another independent review must be handled explicitly; the controller never resets the one-review safeguard silently.
- Persistence schema is version 1, without automatic migration from old Python data or incompatible future machines. Linux/Unix local runtime recovery is tested; Windows service/runtime support is not claimed.
- Local state/evidence can contain internal task data and test output. Keep its private directory on a trusted machine. JEV text is minimized/redacted and source excerpts secret-scanned, but automated detection cannot establish the absence of every domain-specific personal identifier; review data policy and configured exclusions before live intake.
